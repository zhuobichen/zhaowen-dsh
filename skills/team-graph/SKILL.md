# 多 Agent 图编排（team-graph）

当任务**足够复杂**时，不要只做「一条链 + 回滚」的顺序接力（loop 工程）。把任务建模成**图**（graph 工程）：节点是角色 agent 的一次委派，边是数据流/控制流。

## 图的基本单元

| 概念 | 含义 | 例子 |
|------|------|------|
| **节点 node** | 一个角色 agent 的一次委派 | `coder-a` 写模块 A |
| **边 edge** | 上游输出喂给下游 | `analyst → coder` |
| **条件边 conditional edge** | 按结果路由 | 评审通过 → 测试；失败 → 回炉 coder |
| **扇出 fan-out** | 一个节点拆成多个并行节点 | 一个 analyst 拆出 3 个并行 coder |
| **汇聚 join** | 多个并行分支汇到一个节点 | reviewer 汇总所有 coder 的代码 |

## 两类图

1. **模板图**：从预设模板出发（`dev-team` 开发 / `research-team` 调研 / `audit-team` 审计），它们是「锚」，保证不跑飞。
2. **动态图**：根据任务在模板上**改拓扑**——增删节点、拆并行、加条件边。这才是图编排的精髓。

## 编排步骤

1. **选模板**：判断任务类型 → 选最接近的模板图（开发→dev-team；调研→research-team；审查→audit-team）。
2. **自适应改图**：
   - 模块多 → 把 coder 节点 fan-out 成 N 个并行节点
   - 有硬依赖 → 加顺序边（A 的输出是 B 的输入）
   - 有质量门 → 加条件边（reviewer/tester 失败 → 回炉对应节点）
3. **渲染图**：执行前用 Mermaid 把最终 DAG 画出来，让用户**看得见**你要怎么编排。
4. **并行执行**：fan-out 组内的节点用 DSH 的并行能力同时委派 subagent。
5. **汇聚**：join 节点收集所有并行分支的输出，统一把关/汇总。

## 关键原则

- **能并行就并行**：无依赖的子任务不要串行，fan-out 同时跑，省 wall-clock。
- **条件边做闭环**：评审/测试失败用条件边精确回炉，而不是无条件重跑全流程。
- **图要可见**：执行前把 Mermaid DAG 画出来，让编排逻辑透明可审计。
- **模板只是起点**：不要死守模板，按任务动态改拓扑才是图编排的价值所在。
- **小任务不套图**：简单任务（改一行、查个值）直接自己做，不要过度编排。
