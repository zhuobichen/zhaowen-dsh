# 门禁：等待必须终结，取消必须生效

> 版本：v1（2026-11-10）
> 适用范围：**本仓库所有插件、工具、以及任何会给 agent 注册工具的代码**。
> 触发条件：只要一次工具调用可能**长时间不返回**，就必须过这份门禁。
> 自动检查：`node scripts/check-await-safety.mjs`（退出码 1 = 有 [必错]）

---

## 0. 为什么有这份文档

两次真实事故，同一天夜里，同一个形状，第二次是我在修完第一次之后又犯的。

### 事故 A：`host_exec` 卡死 QQ 助手会话

```
agent 用 host_exec 跑 .start-watchdog.cmd
  → 脚本里 `start /B cmd /c "node scripts/qq-watchdog.mjs"` 拉起一个**永不退出**的 watchdog
  → watchdog 继承了 host_exec 给的 stdout/stderr 管道
  → 直接子进程（cmd.exe）exit 0 退出了，但管道还被孙子进程握着
  → `child.on('close')` 要求「管道全关」，永远不触发
  → Promise 永不 resolve → 工具调用**永久挂起**
  → 用户点 UI 的停止键也没用（`exec.signal` 从没被读过）
```

120 秒的 `timeout_ms` 是装饰品：到点只 `child.kill()`，而那在 Windows 上只打**直接子进程**（已经退掉的那个）。

**代价**：QQ 机器人被反复重启到掉线，需要人工扫码；用户等了十几分钟。

### 事故 B：`generate_video` 视频生成成功但工具永不返回

```
视频真的生成好了（页面里已有视频块）
  → 但工具在「取回结果」这段挂住
  → 因为 `cdp.send` 是个裸 Promise：只有收到对应 CDP message 才 resolve，**没有超时**
  → 任何一条 Runtime.evaluate 迟迟不回 → 永不 settle
  → 同样：停止键无效（工具层没把 exec.signal 传进驱动）
```

**代价**：一次视频额度白烧，用户又一次只能重启宿主。

### 共同点

> **都在 `await` 一个「只由对方动作结算」的 Promise，而没有「由自己掌控」的截止点。**

对方是谁不重要——可能是子进程、是 CDP 连接、是 socket、是 HTTP 请求。**只要对方可能永不回应，就必须自己兜底。**

## 1. 两条铁律

### R1 等待必须终结

**每一个 `await` 都必须有「无论如何都会结束」的路径。**

不允许出现「只有事件回调里才有 resolve/reject」的 Promise，除非那个事件**在数学上必然发生**（并且要在注释里写明为什么）。

最低要求：一个 `setTimeout` 兜底，**而且超时分支自己也要 resolve**。

### R2 取消必须生效

**每个注册给 agent 的工具都必须把 `exec.signal` 接上。**

DSH 的 `ToolExecutionToken` 里写着：

```ts
/** Required caller-owned cancellation for this invocation. */
readonly signal: AbortSignal;
```

它是**必填**、由调用方拥有的取消信号。不接 = 用户点停止没有落点。

要求：
- 进入工具就把 `exec.signal` 存起来；
- 每个长轮询/长等待前检查 `signal.aborted`，或在 `pause(ms)` 这类封装里检查；
- 取消时抛一个**明确的**错误（"操作已被用户取消"），不要静默返回。

## 2. 六种反模式（写代码前先对照）

| 编号 | 反模式 | 后果 | 正确做法 |
|---|---|---|---|
| **A1** | `new Promise` 只在 `child.on('close')` / `ws.on('message')` / `req.on('end')` 里 resolve | 事件不来 → 永久挂起 | 加 `setTimeout`，超时**自己也 resolve** |
| **A2** | `setTimeout` 里只 `kill()`，不 resolve | 杀完还在等 `close` → 挂起 | 超时分支里 `finish({timedOut:true})` |
| **A3** | 只杀直接子进程 | 孙子进程活着并握着管道 → `close` 不来 | Windows: `taskkill /PID <pid> /T /F`；然后 `destroy()` stdio |
| **A4** | 工具不读 `exec.signal` | 停止键是装饰品 | 传进驱动，在轮询里检查 |
| **A5** | 用同步语义起 daemon | 必然拖到超时，且服务挂着 | `detached: true` + `stdio:'ignore'` + `unref()`，立刻返回 pid |
| **A6** | 轮询循环没有上限，或上限很长却不检查取消 | 一次误判就是十几分钟白等 | 上限 + 每次迭代检查 abort |

## 3. 各场景的标准写法

### 3.1 Node 子进程（同步语义）

```js
function runProcess(argv, cwd, timeoutMs, signal) {
  return new Promise((resolve) => {
    const started = Date.now()
    let out = '', err = '', settled = false
    const child = spawn(argv[0], argv.slice(1), { cwd, windowsHide: true, shell: false })

    const finish = (code, extra = {}) => {
      if (settled) return
      settled = true
      clearTimeout(timer)
      signal?.removeEventListener('abort', onAbort)
      // 关键：主动关管道，否则孙子进程握着它，宿主侧 close 永远不来
      try { child.stdout?.destroy() } catch {}
      try { child.stderr?.destroy() } catch {}
      try { child.unref() } catch {}
      resolve({ exit_code: code, stdout: out, stderr: err, duration_ms: Date.now() - started, ...extra })
    }

    // Windows 上必须收整棵树
    const killTree = () => {
      try {
        if (process.platform === 'win32' && child.pid) {
          spawnSync('taskkill', ['/PID', String(child.pid), '/T', '/F'], { windowsHide: true, timeout: 10000 })
        } else child.kill('SIGKILL')
      } catch {}
    }

    const timer = setTimeout(() => { killTree(); finish(-1, { timed_out: true }) }, timeoutMs)
    const onAbort = () => { killTree(); finish(-1, { aborted: true }) }
    if (signal?.aborted) { killTree(); finish(-1, { aborted: true }); return }
    signal?.addEventListener('abort', onAbort, { once: true })

    child.stdout?.on('data', (b) => { out += b.toString('utf8') })
    child.stderr?.on('data', (b) => { err += b.toString('utf8') })
    child.on('error', (e) => finish(-1, { stderrOverride: String(e?.message ?? e) }))
    child.on('close', (code) => finish(typeof code === 'number' ? code : -1))
  })
}
```

要点：`settled` 守卫、超时自己结算、收整棵树、`destroy` 管道、接 abort。

### 3.2 常驻服务（daemon）

```js
const child = spawn(argv[0], argv.slice(1), {
  cwd, windowsHide: true, shell: false,
  detached: true,
  stdio: 'ignore',   // 不接任何管道 = 永远不会拖住任何人
})
child.unref()
return { pid: child.pid }   // 立刻返回
```

给用户暴露成 `detach: true` 这样的显式参数，并在工具描述里写清「同步语义 / 常驻请用 detach」。

### 3.3 WebSocket / CDP（请求-应答）

```js
const SEND_TIMEOUT_MS = 30000
cdp.send = (method, params = {}) => new Promise((resolve) => {
  const id = ++seq
  let done = false
  const timer = setTimeout(() => {
    if (done) return
    done = true
    pending.delete(id)
    resolve({ error: { message: `CDP ${method} 超时（${SEND_TIMEOUT_MS}ms 无响应）` } })
  }, SEND_TIMEOUT_MS)
  pending.set(id, (v) => { if (done) return; done = true; clearTimeout(timer); resolve(v) })
  try { ws.send(JSON.stringify({ id, method, params })) } catch (e) { /* 立即 resolve error */ }
})

// 断线也要放掉所有 pending，否则又是一处永久挂起
ws.addEventListener('close', () => {
  for (const [, resolve] of pending) resolve({ error: { message: 'websocket 已断开' } })
  pending.clear()
})
```

### 3.4 长轮询 + 取消

```js
let abortSignal
function throwIfAborted() {
  if (abortSignal?.aborted) throw new Error('操作已被用户取消（abort signal）')
}
async function pause(ms) {
  throwIfAborted()
  await sleep(ms)
  throwIfAborted()
}

// 所有轮询里的 sleep 都换成 pause
while (Date.now() - t0 < deadline) {
  await pause(5000)
  if (await done()) return result
}
```

### 3.5 可以例外的情况

**HTTP 请求体读取**（`req.on('end'|'error')`）是 Node 的标准写法，客户端断开必然触发 `error`/`aborted`，可以不加超时——但要在注释里**写明这一点**，否则下一次审查还会被提出来。

## 4. 门禁检查清单（每次提交插件/工具前逐条打勾）

复制到 PR 描述里，逐条打勾：

```
[ ] R1 本工具涉及的每一个 await，都有一条「无论如何都会结束」的路径
[ ] 没有「只在事件回调里 resolve」的 Promise（除非注释说明事件必然发生）
[ ] 所有 setTimeout 超时分支都自己 settle，不是只 kill
[ ] Windows 上杀进程用 taskkill /T /F，不是 child.kill()
[ ] kill 之后 destroy 了 stdio 管道
[ ] R2 工具读了 exec.signal，长等待里检查 aborted
[ ] 取消时抛明确错误，不静默返回
[ ] 起 daemon 走 detach（detached + stdio:'ignore' + unref），不用同步语义
[ ] 轮询循环有上限，且每次迭代都可能被取消
[ ] 返回值里没有 undefined 字段（会被判 not lossless JSON）
[ ] node scripts/check-await-safety.mjs 通过（或人工确认了每一条 [必错] 是误报）
[ ] 新增的等待点在代码注释里写清「为什么它一定会结束」
```

## 5. 自动检查

```bash
cd <repo>
node scripts/check-await-safety.mjs                 # 扫 packages/
node scripts/check-await-safety.mjs path/to/plugin  # 扫指定目录
node scripts/check-await-safety.mjs --json          # 机器可读
```

输出三档：

| 档位 | 含义 |
|---|---|
| `[必错]` | 结构上就能挂死，**必须改**（或人工确认是误报） |
| `[存疑]` | 没有 deadline，但等的对象通常会自己退出，**需要人工判断** |
| `[提示]` | 测试/脚本目录里的同类写法，不阻塞但有改进空间 |

**已知误报**：间接 resolve（`setTimeout(() => done(v))`，而 `done` 内部才 resolve）会被判成「没结算」。**所以 [必错] 一定要人工过一遍，不要盲信脚本、更不要为了让脚本变绿去改坏代码。**

### 显式豁免：`await-gate: ok`

有些等待在语义上**必然终结**，强行加超时反而是错的。这种地方用一行标记豁免，**理由必须写出来**（否则下一个人无法判断这是深思熟虑还是漏掉了）：

```js
/**
 * await-gate: ok — HTTP 请求体读取，语义上必然终结：`end` 正常完成，
 * 客户端断开/连接重置触发 `error`/`aborted`。对端就是发起请求的客户端，
 * 不存在「永不回应的对端」；加超时反而误伤大请求。
 */
function readJson(req) {
  return new Promise((resolve, reject) => { /* ... */ })
}
```

标记要出现在 `new Promise` / `spawn` 之前 12 行以内。
