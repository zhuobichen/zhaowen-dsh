# dsh-moon-band

输入框上方一行压暗的月光：**月相 + 月龄 + 一句古诗 + 朝代**，右边一个「详解」按钮。
纯装饰，`/moon` 可以收起来。

```
🌒 娥眉月 4.6天 · 「今人不见古时月，今月曾经照古人。」李白《把酒问月》   唐   [详解]
```

点「详解」，下面展开：

```
唐 · 约 725 年（开元十三年）
诗意：今人看不到古时的月亮，可今晚这轮月，却曾经照过古人。
背景：李白借问月感叹人生短暂、宇宙无穷，是他失意时的自问。
（这次没问 AI，读的是缓存）
```

移植自 Claude Code 的 `moon-band` 插件；画那一行的是
[`@zhuobichen/dsh-client-ui-moon-band`](../dsh-client-ui-moon-band)。

## 两半是怎么分工的

| 位置 | 做什么 |
| --- | --- |
| **宿主**（本包） | 读语料（3.18 MB / 46167 句）、算月相与选句、查朝代、开两个只读路由、注册 `/moon` |
| **客户端** | 每 20 秒问一次 `/line`，把那一行画在 `conversation.input.dock`（order 14，压在余额行上面） |

语料留在宿主是因为 46167 句塞不进客户端模块；「这一分钟取哪一句」也必须有唯一说法，
不能每个标签页各算各的。

## 朝代

语料（46167 句、2461 位作者）里**没有朝代字段**，所以靠一张「作者 → 朝代」表。表的取舍
按**出现频率**做：诗句从全语料均匀抽，作者贡献的行数就是他出现的概率。表覆盖出现次数
前 100 的作者，合计 29,690 句（**64%**）。

表外那 36% 是冷门作者，**不显示朝代**（不猜）。但点过一次「详解」之后，AI 会把朝代一起
补出来写进缓存，那之后这句诗就认识朝代了。

## 详解与缓存

`GET /dsh-moon-band/about?line=…`：

- **命中缓存** → 立刻返回，**不问 AI**（面板底部注明"这次没问 AI，读的是缓存"）
- **未命中** → 问一次 AI，拿回 `朝代 / 年份 / 诗意 / 创作背景`，写进
  `$DSH_HOME/plugins/dsh-moon-band/poems-cache.json`，然后返回

缓存按**诗句本身**为键，跨会话、重启都有效。只接受语料里真有的句子——否则这就成了
一个「随便问 AI」的入口。

一次并发点两次只问一次 AI（同一句诗的在途请求会合并）。

## 月相与月龄

**不用平均朔望月公式**：拿 2026 年 10 月的四个相时刻去对，经典公式最大差 −0.72 天，
两参数拟合也压不到 0.75 天以下——月亮走得本来就不匀。这里用**相时刻表 + 相邻两点
线性插值**，表内准到分钟。

**月龄是距上一次新月的真实天数**，不是「相位占比 × 平均月长」：这个朔望月偏长，
占比算法会少报三分之一天，而农历日期是你能自己核的。

表覆盖 **2026-10-03 → 2026-12-31**；表外退回平均公式，并且行首显示 `≈`，不装成事实。

## 那句诗

每分钟换一句，一个 46167 句的库（唐诗 3 万句 + 宋词 1.6 万句，随包分发）。
用一条**满周期线性同余**（`step` 与语料长度互质）选句：一轮会走遍每一句且不重复，
一轮约 32 天；策略每个周期重新播种，所以下一轮是另一种顺序，不是重播。

语料读不到时退回内置 8 句名句，并把 `corpus:false` 报给客户端——不会假装在用你的库。

## 开关

`/moon` 收起／放回，状态写在 `$DSH_HOME/plugins/dsh-moon-band/state.json`，跨会话保留。
